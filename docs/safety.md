# Safety

- Loopback bind only (`CALAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it). The container runs as a non-root user, read-only, with every capability dropped.
- Host header must be a loopback name; writes must be same-origin.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API. There is no worker thread and no child process. Every URL in a hop is a `.example` host and is never sent.
- **The lab holds no credential for any provider.** There is no field that takes one: a body with an unknown key is refused (without naming the key). Mock tokens are labelled MOCK and signed with a public mock key (built with `createECDH` + `createPrivateKey`); they protect nothing.
- **Mock sign-in (rule 11).** A mock run needs `IDP=mock` (the default) AND `ALLOW_MOCK_SIGNIN=1`, and is refused behind a proxy (forwarded headers) or on a non-loopback bind (Docker is the one exception: its compose file publishes on the Mac's `127.0.0.1` alone and says so with `CAL_PUBLISH=loopback`). `NODE_ENV=production` is not a guard: the Docker image sets it.
- **Live mode** can be selected with the toggle only when the owner set `CAL_ALLOW_LIVE=1` (a lab-invented key), `IDP` names a live provider, there is no proxy header and the bind is loopback. `CAL_LAB_MODE=live` makes new workspaces open showing live without checking these; every live run still checks them and gets 403 until they hold. Even when they hold a live run is refused with 501: live is not built until step 3.
- **Nothing the visitor types is echoed.** Ids in the path (use case, vertical, persona, mode) are looked up in fixed lists and answered with fixed text; the workspace id must match `[a-z0-9-]{1,40}` and not look like a credential; unknown body keys are refused without naming them; every JSON answer is masked again by the specific credential detectors, except the MOCK tokens the lab minted for that answer (rule 4: tokens are shown raw). Masking is a heuristic: not every secret has a recognisable shape.
- Every user-supplied value used as an object key or lookup is checked with a type test and `Object.hasOwn` (or a `Map`); `__proto__`, `constructor` and `prototype` are refused.
- Honest status codes: 400 bad input, 403 a guard or a policy, 404 unknown use case, 409 workspace full, 429 too many workspaces, 501 a stub vertical or live not built.
- Writes are serialised per workspace (a promise chain) and capped: 100 runs per workspace (a full workspace refuses the next run with 409 until Reset), 500 workspaces (new ones refused at the cap, nothing is evicted), idle for an hour expires.
- The server writes no file. The one home-directory touch is reading the optional shared settings file (`~/Development/.env`, or `STANDALONE_ENV`) with `util.parseEnv`, taking only `CAL_LAB_MODE`. A bare `MODE` in it is ignored.
- Only `.example` and `.invalid` hosts appear in any shipped text (a doctor check scans the filled story and the manifest in every vertical).
- The source catalog (AI-DEMO2) is read once by `scripts/gen-manifest.mjs`; the app reads only the committed `data/usecases.json`.
