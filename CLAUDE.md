# customer-agent-LAB

Demo-tier standalone app (catalog D24): the customer-facing AI agent of AI-DEMO2 with all 87 use cases in eight tracks. Simulated in Mock; an owner-only Live reaches the identity provider only. **Step 3 of 3 (integration)**: Live mode, doctor/health reporting of it, hub and talk-track entries.

- Run: `npm run build` once, then `./scripts/run.sh` (http://localhost:5600/) or `ALLOW_MOCK_SIGNIN=1 npm start`. Web dev: server, then `npm run dev -w web` (Vite 5602, `/api` proxied). E2E: `npm run e2e` (real Chromium, port 5690; `E2E_CHROMIUM` if Playwright's own browser is not installed). Test: `npm test` (server is `node --test test/*.test.js`, a glob; web is vitest; scripts are `node --test scripts/*.test.mjs`). Preflight `npm run doctor`. Reset `npm run reset`. Smoke `npm run smoke`. Docker: `HOST_PORT=5601 docker compose up --build -d`. Node 26 only. Ports 5600-5699 (app 5600, Docker 5601).
- Core: `data/usecases.json` (generated once by `scripts/gen-manifest.mjs` from the AI-DEMO2 catalog, read only, source file + commit recorded; the app never loads the source), `server/src/manifest.js`, `flow.js` (the pure mock engine: hops from the evidence chain, outcome COMPUTED from `policy.js` + the gateway rules, never read from the manifest), `situations.js` (the lab's inputs per use case), `policy.js` (lab-invented thresholds), `mockjwt.js` (ES256 with `createECDH` + `createPrivateKey`), `cast.js` (3 full vertical packs + 7 stubs), `workspaces.js` (per-workspace write lock, caps), `app.js`, `safety.js` (host/origin checks, rule 11 guards), `netguard.js`, `mask.js` + `credentials.js`.
- Rules that bite: nothing the visitor types is echoed (ids are looked up in fixed lists; errors are fixed text; unknown body keys are refused without naming them); the MOCK tokens minted for an answer are the only credential-shaped text left unmasked (rule 4); static catalog answers use the credential shapes only (prose detectors would corrupt the text); mock runs need `ALLOW_MOCK_SIGNIN=1` + `IDP=mock`, loopback, no proxy header; live is refused unless `CAL_ALLOW_LIVE=1` + a live `IDP` + loopback, and even then a live run is 501 until step 3; every thing used as a key is type-checked (`Object.hasOwn`/`Map`); writes are serialised per workspace, caps refuse whole requests (100 runs, 500 workspaces); thresholds, staged events and personas are lab-invented and labelled; 33 of 87 use cases are guided pages whose outcome is the catalog's label; UC15 is lab-simulated; flag-gated use cases run in mock and name the live feature; ECDSA signatures are randomised, so compare runs without the third token segment.
- Live (step 3, `server/src/live.js`): the one path out. Two calls only, to the one configured PingOne environment: discovery (GET) and a client-credentials token (POST), https (loopback http only for the fake), no redirects, 8 s, 64 KB, `assertAllowed()` before every call, two in flight at most. Needs `CAL_ALLOW_LIVE=1` + `IDP=pingone` + loopback + no proxy (`liveRefusal`) and valid `PINGONE_*` values in the shared file (read by `readLiveSettings`, never put in `process.env`; only settings.js and live.js may name the client secret, a test pins it). A live run is real hops only (no mock mixed in), shows the token masked (first 6, last 4) with decoded claims, lists the use case's steps as `notRun`, never recomputes the outcome (`LIVE_OK`, `LIVE_REFUSED`, `LIVE_UNREACHABLE`; `matchesExpected` and `persona` are null). The netguard allows that one host (`allowHost`, set in index.js after the opt-in check); UDP and resolvers stay loopback-only. UNVERIFIED on a real tenant: tests use `server/test/fakePingone.js` (also used by `npm run e2e` through `CAL_LIVE_TEST_BASE`, which must be http on loopback). Docker is Mock only. No k8s (deferred by the owner). Run conformance and the parent repo's check-drift.sh / check-css.sh by hand. Never print the forbidden-strings file; history scan prints a count only.
- Settings: the shared `~/Development/.env` (mode 600, `STANDALONE_ENV` overrides), `util.parseEnv`; `CAL_LAB_MODE` goes into the environment, the four `PINGONE_*` live keys go to live.js only; never a bare MODE. No k8s (deferred by the owner). Run conformance and the parent repo's check-drift.sh / check-css.sh by hand. Never print the forbidden-strings file; history scan prints a count only.
- Web (`web/`, React + Vite + ReactFlow, vendored `src/styles/standalone-ui.css` byte for byte from AI-DEMO-Standalone `shared/`): `App.jsx` is the shell (dark `shell-bar` with the tablist nav, Mock|Real, Quick Config, Reset, Presenter, theme; the banner right under it). The Agent area is the Agno layout (full page width, owner waiver): `SetupSidebar` (New chat, gateway line, One agent/Several, agent, brain, vertical, use cases with route tags, sessions), `AgentColumn` (chat turns built from the run's hops, What to type chips from `GET /api/prompts`, the selected use case's RunPanel), `EvidenceColumn` (Sequence / Movie reel / Topology / Tokens; `quickConfig.js`: one diagram embedded at a time, saved per workspace), `QuickConfig`, `FullPageEvidence` (`#sequence`, `#reel`). `chat.js` is the Scripted matcher (no model); `server/src/brain.js` is the optional llama.cpp brain (owner opt-in via `CAL_BRAIN_URL`, off by default; it only picks a use case id from the vertical's prompt list, re-checked server side). Routes come from `data/handoff.json`; `docs/use-case-routing.md` (the owner's table, copied unchanged) is its source of truth and a test pins every row (route, app, basis); every What to type prompt is run through `matchPrompt` by `scripts/prompts.test.mjs` against a written-out expected use case; the link carries ids only (`from`, `uc`, `vertical`, `user`) and the card lists exactly `handoffCarry()`; hand-off links are RELATIVE paths from the allow-list in `handoff.js`, only when served under `/customer-agent/`, as buttons (never `<a>`). `layout.css` holds the page layout (same CSS rules as app.css, a repo test pins both). `components/` has the picker, run panel, hop list, token view, extra pages, history and the diagram (`PatternDiagram.jsx` draws the `diagram-studio/1` data that `GET /api/diagram?name=` serves, rule 17), `lib.js` holds labels and the `opens` to extra-page table. App CSS is tokens only (no colour literal, no `prefers-color-scheme`, no `!important`, breakpoints 600/900, BEM names); a repo test pins that.
- Web rules that bite: the side nav is the agent's own four areas; a successful run of a use case with an `opens` value adds an extra page to the one "More" menu beside them (so the shell bar stays one row at 1280 px and up), and Reset removes them; the embedded and full-page sequence open fitted to the width (`data-zoom="fit"`, never above 100%), − / + override and Fit returns; link-outs are plain text (no `<a>`, no URL in web source, a test pins both); a guided run says "guided, not computed" and never renders `matchesExpected` (it is null); lab-invented inputs and the persona carry a LAB-INVENTED tag; the server decides Mock|Live (a refused Live shows the server's words and stays Mock); every API call carries `X-Workspace`, runs carry a browser-made `traceparent`; user and server text is rendered as React text through `visible()`, never as HTML; the server sends a same-origin CSP; server tests use a missing `webDist` so they do not depend on the build.
